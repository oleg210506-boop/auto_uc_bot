# autoUCbot · 1.0.1-rc1

Отдельный сервис продажи PUBG Mobile UC: FunPay → подтверждённый UID → GameCore B2B.
Веб-панель для нескольких индивидуальных доступов; Telegram — срочные уведомления.

**Исправление входа 1.0.1-rc1:** прочитайте `UPDATING.md`. Схема базы, ключи и торговые функции не изменены.

**Статус: тестовый выпуск.** Проверены локальная логика, контракты на заглушках, HTTP и отображение интерфейса. Реальные закупки, ваша сессия FunPay, Docker-сборка и деплой на вашем Railway не проверены без доступов. Не обещается отсутствие всех ошибок или фиксированный счёт Railway.

Подробные HTML-инструкции находятся в общем архиве рядом с этим ZIP. Откройте `START_HERE.html`.

## Развёртывание

1. Содержимое этого ZIP — в корень отдельного приватного репозитория GitHub.
2. Railway: сервис из этого репозитория, Dockerfile, один экземпляр; прикрепить Volume `/data`.
3. Variables: `APP_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `DATA_DIR=/data`, `COOKIE_SECURE=true`, `START_WORKER=true`, `ENABLE_LIVE_PURCHASES=false`.
4. Создать HTTPS-домен сервиса, добавить его как `PUBLIC_URL` (без пути). Отключить Serverless/sleeping.
5. Войти, создать второй доступ, включить 2FA, проверить DEMO.
6. Получить персональные условия GameCore, сохранить ключ, загрузить реальный каталог, подключить FunPay в режиме Observe. После внешней приёмки — отдельное разрешение live и снятие паузы.

`python scripts/generate_secrets.py` генерирует первоначальные значения локально. Не меняйте APP_SECRET на уже существующей базе.

## Что реализовано

- Состав товара `SKU UC × множитель × количество FunPay`; неизменяемый снимок заказа.
- Точная метка продавца + подраздел; другие объявления не обрабатываются.
- GameCore REST-клиент: каталог, создание, все коды заказа, статусы позиций, сверка неизвестного результата; постоянные ключи идемпотентности.
- Один предоплаченный баланс: локальная книга/резервы/сверка и обработка отказа поставщика. Опциональный GET остатка после подтверждения маршрута и формата поставщиком.
- Неофициальный FunPay-адаптер: структурированные оплаченные заказы, сообщения, сессия/опрос, поднятие выбранных подразделов, верифицированные изменения доступности и цены.
- Защита от старых UID, повторов событий, двух одновременных обработчиков одной базы, неизвестного результата покупки/сообщения.
- Роли owner/operator/viewer, серверные сессии, CSRF, scrypt, TOTP и одноразовые резервные коды; секреты шифруются.
- Настройки поведения/сообщений, лимиты, комиссия/прибыль, ручное владение чатом, архив товаров, статистика/CSV/расходы, ручные финансовые подтверждения без внешнего перевода денег.
- Telegram-тревоги с фильтром, несколькими получателями и интервалом повторов.
- Онлайн-копии SQLite, безопасное восстановление до старта, блокировка live до сверки.
- Изолированный DEMO и безопасная очистка только демонстрационных данных.

## Критические внешние условия

- Публичного персонального прайса GameCore нет: он виден после подключения через B2B каталог API.
- Отдельный публичный маршрут баланса не установлен. Начальный режим — ручная сверка **всего фактического остатка**, затем расчёт по операциям бота. Внесение денег снаружи автоматически не определяется без подтверждённого метода API.
- GameCore B2B не имеет бесплатного заказа через `gc_test_`: DEMO реализован внутри autoUCbot, независимо от ключей.
- GameCore не подтверждает ник/существование получателя на данном пути. Формат UID и подтверждение покупателя не доказывают владение аккаунтом.
- Цена при создании может измениться: локальный максимум и резерв — не гарантированный потолок списания у GameCore.
- Требуется договориться о предоплате **без кредитного лимита**, тарифах/комиссиях и отсутствии обязательного статического IP.
- FunPay — неофициальный веб-протокол; ограничение облачного IP, изменение сайта или CAPTCHA требуют вмешательства. Нет обхода антибот-защиты и гарантии непрерывного 24/7 онлайн.
- Первая версия поддерживает обычные лоты FunPay и RUB. Неизвестный формат/валюта → остановка и проверка, не приблизительная конвертация.
- Один диск/процесс на аккаунт. Нельзя параллельно запускать другую копию с теми же ключами и собственной базой.

## Разработка / тесты

Linux + Python 3.13 (либо Linux-контейнер). `fcntl` делает обычный Windows запуск приложения неподдерживаемым; Railway использует Linux. Генератор секретов работает и на Windows.

```sh
python -m pip install -r requirements-dev.txt
python -m compileall -q autoucbot scripts
python -m pytest --cov=autoucbot --cov-branch -q
```

Для локального DEMO задайте переменные из `.env.example`, `DATA_DIR=./local-data`, `COOKIE_SECURE=false`, `ENABLE_LIVE_PURCHASES=false`, `PUBLIC_URL` пусто, затем `python -m autoucbot`. `.env` автоматически не загружается. Не открывайте локальный HTTP с отключённым secure-cookie в публичную сеть.

Читайте `ARCHITECTURE.md`, `SECURITY.md`, `PROTOCOL_SOURCES.md`. Финансовую логику и контрактные проверки меняйте только вместе с тестами.
