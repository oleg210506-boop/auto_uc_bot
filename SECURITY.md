# Безопасность и эксплуатационные границы

- APP_SECRET не публиковать, не менять при обычных обновлениях. Отдельная резервная копия ключа обязательна.
- API-ключ GameCore может расходовать деньги, golden_key — сессия продавца, Telegram-токен — доступ к боту. Только владелец получает раздел подключений. Runtime никогда не передаёт ключи в браузерный JavaScript.
- HTTPS обязателен в Railway. COOKIE_SECURE=true; серверные 8-часовые сессии, HttpOnly/SameSite, CSRF, ограничения частоты входа по имени, пароли scrypt, TOTP и одноразовые recovery-коды.
- 2FA обязательно для всех активных owner/operator перед live. Используйте два индивидуальных аккаунта; операторам не давайте роль owner без необходимости.
- QR генерируется локально сервером, не сторонним сайтом. Исходный секрет 2FA и ключи в базе шифруются; пароли и recovery-коды — не в открытом виде.
- Копии базы всё равно чувствительны: UID, переписка, история продаж и хэши паролей не предназначены для публикации.
- Не делитесь логами с секретами. В исходниках нет реальных пользовательских ключей, демо-баланс не представляет деньги.
- Webhook требует HMAC, допустимое время и уникальное событие; он будит сверку, не служит самостоятельным доказательством выдачи.
- Внешние запросы только к фиксированным origin, TLS проверяется, редиректы API не принимаются. Нет CAPTCHA bypass.
- Автоматическое возобновление не должно превращать неизвестный платёж в новую покупку. Никогда вручную не удаляйте строки batches/keys.
- `/healthz` публичен и не отдаёт токены. Отправка Telegram невозможна при полном отключении всего процесса: используйте внешний монитор при необходимости.
- Дефолтный процесс предназначен для доверенного прокси Railway. Не публикуйте напрямую локальный HTTP; forwarded headers доверяются Railway-инфраструктуре.
- Нельзя запускать копию с теми же FunPay/GameCore на отдельной базе. Нельзя подменять RAILWAY_VOLUME_MOUNT_PATH ручной переменной вместо настоящего диска.

Это не независимый security audit и не гарантия отсутствия уязвимостей. Перед значимым оборотом нужны live-приёмка, проверка поставщика, минимальные лимиты и проверка обновлений зависимостей.
